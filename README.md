# y360-tools — инструменты администратора Яндекс 360

Набор скриптов на чистом Python 3 (только стандартная библиотека) для управления
организацией в Яндекс 360 через REST API (Каталог, Почта, Безопасность, Аудит)
и SCIM.

## Состав

| Файл | Что делает |
|---|---|
| `y360_tui.py` | Псевдографическая консоль (ANSI-терминал): пользователи, отделы, группы, почта, безопасность, аудит-лог, визард «склейки» учёток |
| `y360_gui.py` | То же в GUI (Tkinter, Windows/Linux/macOS). API-слой переиспользуется из `y360_tui.py` — оба файла должны лежать рядом |
| `merge_identities.py` | Отдельный скрипт «склейки» двух учёток при смене фамилии через AD+SCIM (dry-run по умолчанию) |
| `y360.env.example` | Шаблон конфигурации |

## Настройка

```bash
cp y360.env.example .env   # и заполнить значения
```

- `Y360_ORG_ID` — числовой id организации
- `Y360_OAUTH_TOKEN` — OAuth-токен приложения с правами на Каталог/Почту/Безопасность
- `Y360_SCIM_TOKEN` — Bearer-токен SCIM-коннектора (вид `y0_...`)
- `Y360_SCIM_DOMAIN_ID` — domain_id для хоста `https://{domain_id}.scim-api.passport.yandex.net`
- опционально: `Y360_V1_TOKEN` / `Y360_V2_TOKEN` (разные токены для v1/v2), `Y360_TIMEOUT`

Токены читаются только из окружения/`.env`, на экран и в логи выводятся только
маской вида `y0_…abc`. `.env` в репозиторий не попадает.

## Запуск

```bash
python3 y360_tui.py --mock      # демо-данные вымышленной организации, сеть не трогается
python3 y360_tui.py --check     # показать замаскированную конфигурацию
python3 y360_tui.py             # read-only: только GET, записи заблокированы
python3 y360_tui.py --write     # разрешить записи (каждый шаг с подтверждением)
python3 y360_tui.py --selftest  # автотесты на моках, без TTY

python y360_gui.py --mock       # GUI с демо-данными (Windows: python.org-сборка уже включает Tcl/Tk)
```

Управление в TUI: стрелки / `j` `k`, цифры 1–9 — быстрый выбор, Enter — открыть,
Backspace или `x` — назад, `q` — выход.

## «Склейка» учёток (merge)

Сценарий: сотрудник сменил фамилию в AD, SCIM-коннектор потерял якорь `mail` и
создал дубликат, а ящик с письмами остался на старом аккаунте. Операции merge в
API Яндекс 360 нет; скрипты реализуют другой подход: дубликат удаляется, старый
аккаунт переименовывается (SCIM `userName` → каталог `nickname`/`default_email`/
`display_name`), старый адрес становится алиасом — письма продолжают падать в
тот же ящик.

Порядок шагов критичен (подробности — в докстринге `merge_identities.py`).

**Важно:** процедура составлена по документации Яндекса и логике SCIM/RFC7644,
живым прогоном не подтверждена. Сначала `--mock`, затем read-only-просмотр на
своей организации, боевые шаги — только осознанно и с остановленной
SCIM-синхронизацией.

## Безопасность

- По умолчанию все записи запрещены; включаются явным `--write` (TUI/CLI) или
  чекбоксом «Режим записи» (GUI), каждое действие — с подтверждением.
- Между запросами пауза ~0.5 с, 3 ретрая с экспоненциальным backoff.
- Демо-данные — полностью вымышленная организация, любые совпадения случайны.

Требуется Python 3.8+. Зависимостей нет.
